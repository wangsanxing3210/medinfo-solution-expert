# 公文格式 .docx 输出规范（official-docx-format）

> 供「方案 → 公文格式 .docx」转换时参考。适用场景：方案需提交政府机关、卫生健康主管部门、医院评审委员会，或作为正式归档文档时，建议按本规范输出；纯内部流转 / 微信传阅仍以 Markdown 或普通 Word 即可。

## 一、适用判断

| 场景 | 推荐格式 |
|------|----------|
| 提交卫健委 / 政府 / 医院评审 | 公文格式 .docx（本规范） |
| 正式归档、盖章 | 公文格式 .docx + 落款日期 |
| 内部流转、评审讨论 | Markdown / 普通 Word |
| 公众号 / 网页发布 | HTML / Markdown |

## 二、页面与版式（GB/T 9704-2012 关键参数）

| 项目 | 参数 | 说明 |
|------|------|------|
| 纸张 | A4（210mm×297mm） | 公文唯一用纸 |
| 上边距 | 3.7cm | |
| 下边距 | 3.5cm | |
| 左边距 | 2.8cm | |
| 右边距 | 2.6cm | |
| 行距 | 固定值 28 磅 | 正文 |
| 正文字号 | 三号（16pt） | |
| 每页行数 | 约 22 行 | 由行距自然形成 |

## 三、字体与标题层级映射

| Markdown | 层级 | 字体 | 字号 | 其他 |
|----------|------|------|------|------|
| `#` 方案标题 | 标题 | 方正小标宋简体（缺则宋体） | 二号（22pt） | 居中，段前段后各 20pt |
| `##` 文档摘要/目录/章节 | 一级 | 黑体 | 三号（16pt） | 段前 12pt 段后 6pt，不缩进 |
| `###` 小节 | 二级 | 楷体_GB2312 | 三号（16pt） | |
| `####` 子节 | 三级 | 仿宋_GB2312 | 三号（16pt） | 加粗 |
| 正文 | — | 仿宋_GB2312 | 三号（16pt） | 首行缩进 2 字符（32pt），行距固定 28 磅 |
| 表格 | — | 仿宋 | 小四（12pt） | 表头加粗居中，网格线 |

> 西文字体统一 Times New Roman（公文惯例）。所有文字颜色统一为黑色（含标题、表格、引用）。中文字体缺失时回退：方正小标宋简体→宋体，楷体_GB2312→楷体，仿宋_GB2312→仿宋。

### 导航目录（自动生成）

docx 默认自动带**可导航目录**，两种使用方式：

1. **文档内目录页**：正文前自动插入「目录」节（Word TOC 域 `TOC \o "1-3" \h \z \u`），位置**紧跟文档摘要之后**（文档无摘要节时，插入主标题后、首章节前）。打开文档后：
   - 若弹出"是否更新域"→ 选"是"，目录即生成；
   - 未弹出 → 全选（Ctrl+A）后按 **F9** 更新域；
   - 目录条目带超链接，按住 Ctrl 点击可跳转对应章节。
2. **Word 左侧「导航」窗格**：章节标题（##/###/####）使用内置 Heading 1/2/3 样式，导航窗格自动显示层级结构，点选即可跳转。

> 实现要点：标题必须用内置 Heading 样式（或设置 outline level），**普通段落即使设置了字体也不进目录、不进导航窗格**。转换脚本已自动处理：`##`→Heading 1（黑体）、`###`→Heading 2（楷体）、`####`→Heading 3（仿宋），并清理了 Heading 样式的默认蓝色/加粗。

## 四、转换方法（两种路径）

### 路径 A：python-docx 脚本（推荐，格式可控）
- 若 agent 环境存在转换脚本（如 `md2official_docx.py`），直接调用：
  ```bash
  python3 md2official_docx.py 方案.md -o 方案.docx
  python3 md2official_docx.py 方案.md -o 方案.docx --body-font 仿宋 --title-font 宋体
  ```
- 若无脚本，用 python-docx 按上表参数手工生成；关键点：中文字体须同时设置 `w:eastAsia`，否则 Word 不生效。

### 路径 B：pandoc（快速，需系统安装）
```bash
pandoc 方案.md -o 方案.docx --reference-doc=公文参考.docx
```
- `公文参考.docx` 为预置好字体/页边距的参考模板；无参考模板时 pandoc 默认格式不满足公文要求。

## 五、转换后必做清单（交付前）

1. **字体核对**：抽查标题（小标宋 22pt）、章节（黑体 16pt）、正文（仿宋 16pt）是否生效——Word 打开后若字体缺失会静默替换，须提醒用户安装字体。
2. **页边距核对**：上 3.7 / 下 3.5 / 左 2.8 / 右 2.6。
3. **表格核对**：Markdown 表格是否完整转出、表头加粗、跨页断行是否合理。
4. **图表核对**：Mermaid / ASCII 架构图在 Word 中无法渲染——**必须转换为图片（截图/导出 PNG）后嵌入**，或在转换时标注"（图示见附件）"。
5. **内容一致性**：docx 与 Markdown 源内容逐节核对，不得因转换丢章节、丢表格。
6. **导航核对**：确认章节标题为 Heading 样式（Word「导航」窗格可见层级）、目录页已插入 TOC 域（打开按 F9 可更新）。

## 六、常见问题

| 问题 | 处理 |
|------|------|
| Word 提示缺"方正小标宋简体/仿宋_GB2312" | 提醒用户安装对应字体；或改用系统已有字体（宋体/仿宋/黑体/楷体） |
| 表格跨页被切断 | 在 Word 中勾选表格行"允许跨页断行"，或缩小表内字号 |
| 架构图是 Mermaid 代码 | 转图片嵌入；无法转图时保留 Markdown 附件并在 docx 中标注 |
| 需要红头（发文机关标志） | 本规范为**简化公文**（无红头）；如需红头版，另行排版发文机关标志（红色小标宋）、发文字号、红色分隔线 |
| 需要页码 | 公文页码：4 号半角宋体阿拉伯数字，置于版心下边缘之下，数字左右各放一条一字线（—1—） |

## 七、合规提醒

- 方案涉及机构名、金额、案例一律脱敏（同 `SKILL.md` AP-07 反模式），docx 输出同样遵守。
- 若方案用于对外报送，建议在文末加"编制单位 / 编制日期 / 版本号"落款，供盖章归档。
